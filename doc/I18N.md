# Gestione Lingue

Le lingue sono gestite tramite file JSON.

In sviluppo i file si trovano in:

```text
backend/locales/
```

Nell'app portable vengono copiati in:

```text
PlannerApp/locales/
```

## File lingua

Esempio:

```text
it.json
en.json
```

Il nome del file corrisponde al codice lingua.

Esempi validi:

```text
it
en
fr
es
pt-BR
```

## Struttura JSON

Il progetto usa un dizionario piatto:

```json
{
  "settings.title": "Impostazioni",
  "sideBar.project": "Progetti",
  "taskModal.actions.save": "Salva"
}
```

Questa struttura e semplice da leggere nel frontend:

```jsx
jsonLanguage['settings.title']
```

Il backend richiede un oggetto non vuoto, con chiavi non vuote e valori stringa.
Array, oggetti annidati, numeri e valori null non sono dizionari validi. Il
controllo non richiede tutte le chiavi del dizionario di default: la gestione
delle singole chiavi mancanti e l'integrazione delle nuove traduzioni restano
separate e sono ancora nella TODO.

## Validazione e fallback

Il cambio lingua accetta solo codici nel formato mostrato sopra e verifica il
file esterno prima di salvare la preferenza: deve essere presente, leggibile
e contenere un dizionario valido. Una richiesta non valida restituisce `400`
senza modificare il DB. Anche `get_available_languages` esclude file non validi,
illeggibili o directory il cui nome termina con `.json`.

Durante il caricamento il file potrebbe essere stato eliminato o danneggiato
dopo il salvataggio. In quel caso si provano nell'ordine:

1. lingua salvata: file esterno, poi copia inclusa in `DEFAULT_LOCALES_DIR`;
2. italiano: file esterno, poi copia inclusa;
3. inglese: file esterno, poi copia inclusa.

I percorsi gia provati non vengono ripetuti. Il fallback non sovrascrive file,
non cambia la preferenza salvata e non unisce le chiavi di dizionari diversi.
Il frontend continua a ricevere soltanto un dizionario piatto. Se tutti i file
sono inutilizzabili, la route restituisce un errore JSON `503` invece di un
errore interno non gestito.

## Errori desktop prima di React

Le chiavi `desktop.errors.*` sono lette anche da Python per i messaggi fatali di
avvio e arresto. In questa fase si usa la lingua del sistema (it/en), non quella
salvata nel DB: una migrazione o un database guasto non devono impedire la
segnalazione. Si applicano i valori inclusi nel bundle e poi quelli esterni, con
fallback inglese; se tutti i dizionari sono illeggibili restano messaggi inglesi
di emergenza. Questo fallback e specifico degli errori desktop, non aggiorna i
file lingua dell'utente e non sostituisce la futura gestione delle chiavi React.

## Aggiungere una nuova lingua

Per aggiungere una lingua nell'app portable:

1. copia un file esistente, per esempio `it.json`;
2. rinominalo, per esempio `fr.json`;
3. traduci i valori;
4. riavvia o ricarica l'app.

Il backend espone le lingue disponibili leggendo e validando i file presenti in
`LOCALES_DIR`; una nuova lingua compare solo quando il dizionario e utilizzabile.

## Regola importante

I file esterni in `PlannerApp/locales/` non vengono sovrascritti all'avvio.

Se manca un file default, viene copiato dal bundle. Se invece esiste gia, viene lasciato invariato per non perdere modifiche dell'utente.
