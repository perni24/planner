# Gestione Lingue

Le traduzioni sono file JSON in `backend/locales/` (sviluppo) e in
`PlannerApp/locales/` (portable). Il nome del file e il codice lingua: `it.json`,
`en.json`, `pt-BR.json`.

## Struttura

Un dizionario piatto con chiavi puntate e valori stringa:

```json
{
  "settings.title": "Impostazioni",
  "taskModal.actions.save": "Salva"
}
```

Nel frontend si usa `jsonLanguage['settings.title']` da `useLanguage()`. Una chiave
nuova va aggiunta a tutti i file lingua. Un dizionario e valido se e un oggetto non
vuoto con chiavi non vuote e valori stringa; non serve che contenga tutte le chiavi.

## Validazione e fallback

- Il cambio lingua salva la preferenza solo se il file esterno esiste ed e valido,
  altrimenti `400`. L'elenco delle lingue mostra solo i file validi.
- Al caricamento, se il file e stato eliminato o danneggiato, si provano in ordine
  la lingua salvata, l'italiano e l'inglese, ognuna prima esterna e poi inclusa
  nell'app. Il fallback non modifica file o preferenza e non unisce dizionari
  diversi; senza dizionari utilizzabili la risposta e `503`.
- I messaggi di errore desktop (`desktop.errors.*`) usano la lingua del sistema
  (it/en) e non il database, cosi funzionano anche con un database guasto; senza
  dizionari leggibili restano messaggi inglesi.

## Aggiungere una lingua

Copia un file esistente in `PlannerApp/locales/` con il nuovo codice (es.
`fr.json`), traduci i valori e riavvia: la lingua compare quando il file e valido.

## File esterni e aggiornamenti

All'avvio la portable copia i file lingua mancanti e non sovrascrive quelli
esistenti, per non perdere le modifiche dell'utente. Per questo le chiavi aggiunte
da una nuova versione non arrivano a chi ha gia i file (vedi `TODO.md`).
